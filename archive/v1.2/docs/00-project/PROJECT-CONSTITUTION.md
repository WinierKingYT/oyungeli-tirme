# Project Constitution

Status: `BOOTSTRAP — REQUIRES PROJECT RATIFICATION`

## Technical north star

Any core gameplay failure must be observable and reproducible. A new mechanic should be addable without modifying unrelated systems or duplicating canonical state.

## Non-negotiable principles

1. Repository reality outranks memory and conversation.
2. One canonical owner exists for each mutable domain fact.
3. Production work requires an approved, scoped task and active lease.
4. The implementer is not the final acceptance authority.
5. Evidence, not elapsed time or confidence language, closes work.
6. Material ambiguity is surfaced, never silently resolved.
7. Frozen decisions change only through an approved change request and ADR.
8. Failure, recovery, performance, multiplayer, and persistence behavior are designed before production acceptance.
9. New abstractions solve demonstrated present problems.
10. A process rule may be revised only with rationale, version, migration note, and validation.

## Human authority

The human project owner approves vision, scope, milestones, high-cost decisions, implementation leases, exceptions, releases, and process changes. AI agents may analyze, propose, implement within a lease, test, and review according to separated roles.

## Prohibited shortcuts

- implementation from an unreviewed conversation;
- undocumented architecture changes;
- self-acceptance;
- “works on my machine” as closure evidence;
- disabling a failing control;
- hiding limitations or pre-existing failures;
- introducing a second owner for the same state;
- accepting a feature solely because it compiles or has tests.

## Ratification

Replace this bootstrap status only after project discovery verifies the actual engine, repository, team, platforms, build system, risks, and release target.
