# Postmortem Standard

A postmortem is required for P0/P1 escapes, corrupted state/save, security or authority breach, lost work, failed release, major performance regression, repeated softlock, or milestone abort.

Required sections:

1. impact and scope;
2. factual timeline;
3. detection and response;
4. technical cause;
5. contributing system conditions;
6. why existing controls did not detect/prevent it;
7. recovery and validation;
8. recurrence-prevention actions with owner and evidence;
9. process changes, if justified.

The objective is system learning, not assigning personal blame.
