# Process Improvement

Process version: `1.1.0`

Change the process when evidence shows a repeated failure, unnecessary cost, missing control, or disproportional rigor. Each change records problem, evidence, proposed rule, affected workflows, migration, risk, validation, approver, and new version.

Do not add rules merely because they sound prudent. Controls must address a demonstrated risk or explicit project obligation.

Quarterly or milestone audit questions:

- Which failures escaped and why?
- Which gates produced useful signal?
- Which controls were routinely bypassed or misunderstood?
- Where did cycle time grow without quality gain?
- Which recurring correction belongs in a rule, skill, validator, or test?
